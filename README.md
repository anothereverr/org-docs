# org-docs — Centralized Wiki Portal

Aggregates wikis from all repositories in a GitHub organization into a single MkDocs portal, published automatically on GitHub Pages every 30 minutes.

## How it works

```
GitHub wikis (50+ repos)
        ↓
  discover_wikis.py   — GitHub API: find repos with has_wiki=true
  clone_wiki.py       — git clone/update each .wiki.git repo
  copy_content.py     — namespace content under docs/{slug}/
  rewrite_links.py    — fix image paths and wiki-style links
  generate_nav.py     — build mkdocs.yml with full nav
        ↓
  mkdocs gh-deploy    — publish to GitHub Pages
```

## Setup (one-time)

### 1. Create the repository

Create a new GitHub repo in your organization (e.g. `org-docs`).

### 2. Enable GitHub Pages

Go to **Settings → Pages** and set:
- Source: **Deploy from a branch**
- Branch: `gh-pages`

> The `gh-pages` branch is created automatically on first deploy.

### 3. Create a Personal Access Token (PAT)

Go to **Settings → Developer settings → Personal access tokens → Fine-grained tokens** and create a token with:
- **Repository access**: All repositories in the organization (or select repos)
- **Permissions**: `Contents` (read) — to clone wikis; `Contents` (write) on `org-docs` — to push docs

For a classic PAT: scope `repo` covers everything.

### 4. Add repository secrets and variables

In `org-docs` → **Settings → Secrets and variables → Actions**:

| Type | Name | Value |
|---|---|---|
| Secret | `GH_PAT` | Your Personal Access Token |
| Variable | `GH_ORG` | Your GitHub organization name |
| Variable | `MKDOCS_SITE_NAME` | *(optional)* e.g. `Acme Documentation` |
| Variable | `MKDOCS_SITE_URL` | *(optional)* e.g. `https://acme-org.github.io/org-docs/` |
| Variable | `MKDOCS_REPO_URL` | *(optional)* e.g. `https://github.com/acme-org/org-docs` |

### 5. Push this repo to GitHub

```bash
git init
git add .
git commit -m "chore: initial setup"
git remote add origin https://github.com/YOUR_ORG/org-docs.git
git push -u origin main
```

The first sync will run automatically within 30 minutes, or you can trigger it manually.

## Running manually

### Trigger via GitHub Actions UI

Go to **Actions → Sync Wikis and Deploy → Run workflow**.

Options:
- **Dry run**: discover wikis but do not commit or deploy
- **Repo filter**: sync only one specific repo (useful for testing)

### Test a single repo locally

```bash
export GH_TOKEN=ghp_yourtoken
export GH_ORG=your-org

pip install -r requirements.txt

# Full sync
python scripts/sync_wikis.py --org "$GH_ORG"

# Single repo (no deploy)
python scripts/sync_wikis.py --org "$GH_ORG" --repo-filter my-service --log-level DEBUG

# Dry run (no writes)
python scripts/sync_wikis.py --org "$GH_ORG" --dry-run
```

After running locally, build and preview:

```bash
mkdocs serve
# Open http://127.0.0.1:8000
```

## Environment variables reference

| Variable | Required | Description |
|---|---|---|
| `GH_TOKEN` | Yes | GitHub PAT for API access and wiki cloning |
| `GH_ORG` | Yes | GitHub organization name |
| `MKDOCS_SITE_NAME` | No | Portal title (default: "Organization Documentation") |
| `MKDOCS_SITE_URL` | No | Full URL of the GitHub Pages site |
| `MKDOCS_REPO_URL` | No | URL of this repo (shown in MkDocs header) |
| `REPO_FILTER` | No | Sync only this repo slug/name |
| `DRY_RUN` | No | Set to `true` to skip writes |
| `LOG_LEVEL` | No | `DEBUG` / `INFO` / `WARNING` / `ERROR` |

## Troubleshooting

**Wiki not appearing in the portal**
- Check `has_wiki: true` is set on the repo (Settings → Features → Wikis)
- Verify the wiki has at least one page (the wiki must be initialized)
- Check the Actions log for clone errors

**Images not loading**
- Images must be uploaded directly to the wiki (not referenced from the main repo's file tree)
- External image URLs (https://...) are left unchanged and should work as-is

**Links between pages are broken**
- Wiki-style links like `[API](API)` are rewritten to `[API](API.md)` at sync time
- If a link target does not match any known page in that wiki, it is left unchanged and a warning is logged
- Check the Actions log for `Unresolved wiki link` warnings

**Build fails with `mkdocs build` errors**
- Check the Actions log for the specific error
- Common cause: a rewritten link points to a page that was deleted or renamed

**Rate limit errors**
- The sync handles GitHub API rate limits automatically via the `Retry-After` header
- For organizations with 1000+ repos, consider adding `--skip-archived` to reduce API calls
